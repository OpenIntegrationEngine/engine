# Open Integration Engine 4.7.0 release notes

## Highlights

- **Stronger XML and database security.** Closes SQL injection and XML external entity vulnerabilities in the Database Connector API, XML batch processing, and XSLT transformer input. Additional hardening protects custom metadata searches and strict HL7 v2 XML parsing.
- **More control over HTTP connections.** HTTP Sender can bind outgoing connections to a selected local address. HTTP Listener supports a configurable maximum request-header size. [Sender change](https://github.com/OpenIntegrationEngine/engine/commit/d4d1122d1), [listener change](https://github.com/OpenIntegrationEngine/engine/commit/83d7c1a20).
- **Recent message-search filters.** Quickly reuse up to ten recent filters per channel. History stays in Administrator process memory rather than being written to local preferences, where search terms could expose sensitive data. [Feature](https://github.com/OpenIntegrationEngine/engine/commit/cab7392ec), [memory-only storage](https://github.com/OpenIntegrationEngine/engine/commit/924097130).
- **Batch submission with every message ID.** The new `POST /api/channels/{channelId}/batchMessagesWithObj` endpoint returns the IDs of all messages produced by a successful batch submission. It respects the channel's Process Batch setting; channels without batch processing return a single ID. [API change](https://github.com/OpenIntegrationEngine/engine/commit/893ae635b).
- **JDBC drivers in custom resources work again.** On Java 9 and later, a JDBC driver supplied through a library resource could not be loaded. The resource's isolated classloader could not see Java platform classes such as `java.sql.Driver`. Database Reader and Database Writer connectors not using JavaScript failed to deploy with `NoClassDefFoundError: java/sql/Driver`, and scripts using `DatabaseConnectionFactory`, including Database Reader and Writer connectors in JavaScript mode, failed when opening a connection. This blocked using a driver version other than the one shipped with the server, or different driver versions in different channels. Isolated resources can now see Java platform classes while remaining isolated from the engine's own libraries. Originally reported in [Mirth Connect discussion #5079](https://github.com/nextgenhealthcare/connect/discussions/5079). Thanks to @paul-hristea. [Fix](https://github.com/OpenIntegrationEngine/engine/pull/340).
- **Reliability improvements.** Fixes Oracle JDBC batch inserts, duplicate server-plugin lifecycle calls, and CLI hangs on authentication or connection failures.
- **Modernized source builds and containers.** Gradle replaces Ant, dependency checksums are verified, and an in-repository Docker build supports startup configuration through environment variables and mounted secrets, including database and JVM settings. Automated smoke tests cover five database types. [Container support](https://github.com/OpenIntegrationEngine/engine/commit/5423492e9).

## Breaking changes and upgrade considerations

### Initial administrator credentials and password policy

**Fresh databases no longer initialize with `admin/admin`.** Set `server.initialadminpassword` before the database's first initialization, or retrieve the generated administrator password from the first-startup server log. Changing this property later does not reset an existing account. Existing database credentials are retained. Update unattended installation and provisioning scripts accordingly. [Credential initialization change](https://github.com/OpenIntegrationEngine/engine/commit/423df182f).

The packaged default configuration now sets a **15-character password minimum**, `password.retrylimit = 100`, and `password.lockoutperiod = 1` (**one hour**). These are new configuration defaults; preserved configuration files are not automatically rewritten to these values. Review the defaults when replacing configuration files or provisioning a new server. [Policy change](https://github.com/OpenIntegrationEngine/engine/commit/e8afb74a7).

### XML messages containing DOCTYPE

**DOCTYPE declarations are rejected** in source XML passed to XSLT steps, XML batch splitting by element name, level, or XPath query, and the HL7 v2 strict XML parser. Integrations using DTDs or entity declarations in these inputs must send self-contained XML without DOCTYPE declarations. Ordinary XML and namespace handling remain supported; the strict HL7 XML parser also preserves CDATA content. [XSLT fix](https://github.com/OpenIntegrationEngine/engine/commit/1e87457d3), [batch fix](https://github.com/OpenIntegrationEngine/engine/commit/10627668e), [strict HL7 fix](https://github.com/OpenIntegrationEngine/engine/commit/4f4809d14), [CDATA fix](https://github.com/OpenIntegrationEngine/engine/commit/03eefcfe0).

XSLT stylesheets remain trusted configuration: external stylesheet imports/includes and `document()` access are still supported. The source-message hardening does not impose a blanket external-resource ban on stylesheets.

### HTTP Listener header limits

The new request-header-size setting retains the **8192-byte** limit for legacy configurations that omit it. A configured value must resolve to a positive integer; invalid, unresolved, zero, or negative values fail connector startup. Check channel templates and API-imported settings before deployment. [Final validation behavior](https://github.com/OpenIntegrationEngine/engine/commit/fa57d5d63).

### Microsoft SQL Server JDBC encryption

The bundled Microsoft driver changes from **8.4.1.jre8 to 10.2.4.jre11**. Starting with 10.2, Microsoft's driver enables `encrypt=true` by default and also validates certificates when the server forces encryption, even if the client specifies `encrypt=false`. Connections that previously worked without a trusted, matching server certificate can fail after upgrading. Verify TLS certificates and trust configuration for deployments using the Microsoft driver, including engine-database and channel connections. This particular change does not apply to connections using jTDS. [Dependency change](https://github.com/OpenIntegrationEngine/engine/commit/4af696764), [Microsoft's 10.2 changes](https://learn.microsoft.com/en-us/sql/connect/jdbc/release-notes-for-the-jdbc-driver?view=sql-server-ver17#changes-in-102).

### Bundled Java runtime

Installers that bundle a Java runtime now include **Eclipse Temurin 21** instead of **Azul Zulu 17**. Installations that run on a separately installed Java are not affected, and Java 17 remains the minimum supported version. If you use custom JVM options or rely on Java 17-specific behavior, check them against Java 21 before upgrading.

### API consumers and custom extensions

- **Custom metadata filters must name configured columns exactly.** Unknown names, including incorrect casing and stale filters referring to removed or renamed columns, are rejected before a search query runs. This applies to retrieval, counting, removal, reprocessing, and export. Synchronous invalid requests can return HTTP 500; asynchronous reprocessing failures are logged. [Validation change](https://github.com/OpenIntegrationEngine/engine/commit/9359d9a82).
- **`selectLimit` is deprecated and no longer used.** Database table metadata lookups no longer execute a supplied `selectLimit` query template; they use quoted identifiers and a zero-row query, with JDBC metadata fallback. Custom "Select with Limit Query" values in the Database Drivers settings and `dbdrivers.xml` are ignored. The `selectLimit` query parameter of `POST /connectors/jdbc/_getTables`, and the matching argument of `DatabaseConnectorServletInterface.getTables` in client-core, are deprecated and ignored, and will be removed in an upcoming release. Java code calling `getTables` will need to drop that argument when upgrading to the client-core library from that release. [Fix](https://github.com/OpenIntegrationEngine/engine/commit/d38accecf).
- **Custom controller/servlet implementations need updating.** `EngineController` adds an abstract five-argument `dispatchRawMessage` overload, and `MessageServletInterface` adds `processBatchMessage`. The existing four-argument dispatch API remains available to callers. [API change](https://github.com/OpenIntegrationEngine/engine/commit/893ae635b).
- **The standalone extension JNLP endpoint is removed.** Extension resources are included directly in the main launch descriptor, reducing startup requests. Update custom launchers that fetch `/webstart/extensions/<extension>.jnlp` and subclasses overriding the removed `getExtensionJnlp(String)` method. Main launch descriptors and extension JAR serving remain available. [JNLP changes](https://github.com/OpenIntegrationEngine/engine/commit/a403863a9), [endpoint removal](https://github.com/OpenIntegrationEngine/engine/commit/0205efbde).
- **Other custom Java integrations:** the Microsoft driver removes `getAADSecretPrincipalId`; the server-plugin accessor now returns a snapshot, and plugin de-duplication uses `equals`/`hashCode`; missing synchronized global-map keys now throw `IllegalArgumentException` instead of `NullPointerException`. Check custom code relying on these APIs or behaviors. [Microsoft changes](https://learn.microsoft.com/en-us/sql/connect/jdbc/release-notes-for-the-jdbc-driver?view=sql-server-ver17#changes-in-102), [plugin collection](https://github.com/OpenIntegrationEngine/engine/commit/f421b3ca7), [global-map error](https://github.com/OpenIntegrationEngine/engine/commit/2e0ff419b).

### Administrator, CLI, JSON, and build tooling

- **Administrator now checks for JavaFX at startup.** Use a launcher/runtime with the `javafx.graphics` module available; the client stops with a prerequisite message when it is missing. Java 17 remains the minimum Java version; that requirement was introduced in 4.6.0. [Prerequisite check](https://github.com/OpenIntegrationEngine/engine/commit/86dec16ea).
- **CLI startup failures now return meaningful nonzero exit codes.** Automation should handle authentication, connection, configuration, usage, and unreadable-script failures. This does not guarantee that every failed command inside a script changes the process exit code. [CLI fix](https://github.com/OpenIntegrationEngine/engine/commit/11ad74434).
- **Jackson-based JSON paths have new parsing limits.** Jackson Core 2.18.8 introduces limits absent in the bundled 2.14.3 baseline, including nesting depth and token lengths. Test unusually deep or large JSON handled through Jackson-based utilities/custom code; this is not a claim that every OIE JSON parser uses Jackson. See [security review](security-review.md) for the limits and upstream references.
- **Source-build automation must migrate from Ant to Gradle.** Use the included wrapper, for example `./gradlew build -PdisableSigning=true`; source directories now follow the standard Gradle layout. Import the repository as a Gradle project instead of using the removed Eclipse project files. [Build migration](https://github.com/OpenIntegrationEngine/engine/commit/24c96f509), [source moves](https://github.com/OpenIntegrationEngine/engine/commit/8a2dc59f3).

## Fixes and improvements

- Keep Oracle prepared statements open until queued JDBC batch work executes, fixing failures caused by prematurely closed statements. [Fix](https://github.com/OpenIntegrationEngine/engine/commit/864ede756).
- Restore access to Java platform classes such as `java.sql` for isolated resource libraries, while retaining isolation from engine application classes. [Fix](https://github.com/OpenIntegrationEngine/engine/commit/2085b4c89).
- Start and stop registered server plugins once when a plugin implements multiple extension interfaces; preserve plugin ordering. [Fix](https://github.com/OpenIntegrationEngine/engine/commit/aac955884), [final implementation](https://github.com/OpenIntegrationEngine/engine/commit/f421b3ca7).
- Ignore `undefined` preprocessor results instead of replacing the message, and treat blank channel scripts as absent. [Preprocessor fix](https://github.com/OpenIntegrationEngine/engine/commit/3960aabfb), [blank-script fix](https://github.com/OpenIntegrationEngine/engine/commit/cba21a202).
- Make `channelName` available to channel postprocessor scripts. [Fix](https://github.com/OpenIntegrationEngine/engine/commit/ac3a398cc).
- Report a clear `IllegalArgumentException` when global-variable lock/unlock helpers receive a key that was never registered for synchronization, instead of a null-pointer failure. [Fix](https://github.com/OpenIntegrationEngine/engine/commit/2e0ff419b).
- Cache the compiled tree-search regular expression and use the connector-specific dashboard icon. [Search improvement](https://github.com/OpenIntegrationEngine/engine/commit/8c1111ba3), [icon fix](https://github.com/OpenIntegrationEngine/engine/commit/f844f6da3).
- Correct launch-descriptor branding and reduce Administrator startup requests by embedding extension launch resources. [Branding](https://github.com/OpenIntegrationEngine/engine/commit/a08c1145f), [launch resources](https://github.com/OpenIntegrationEngine/engine/commit/a403863a9).
- Replace the expired signing certificate used for signed artifacts. [Certificate change](https://github.com/OpenIntegrationEngine/engine/commit/590683161).
- Make logging-library discovery independent of hard-coded Log4j JAR versions. [Fix](https://github.com/OpenIntegrationEngine/engine/commit/85188d583).
- Add a final-comment safeguard to the custom JVM-options template so options inserted above it retain their newline, and fix Java detection/server startup under PowerShell 5.1. [JVM options](https://github.com/OpenIntegrationEngine/engine/commit/70b627dff), [PowerShell](https://github.com/OpenIntegrationEngine/engine/commit/e76591953).

## Build and validation improvements

Dependencies are resolved from a centralized version catalog with checksum verification and distribution-placement checks. Netty and Log4j modules share version definitions to prevent mismatched family upgrades. Renovate maintains dependency updates. [Dependency migration](https://github.com/OpenIntegrationEngine/engine/commit/29c5df718), [family alignment](https://github.com/OpenIntegrationEngine/engine/commit/81a6f59b6).

The Docker-based CI harness exercises Derby, PostgreSQL, MySQL, Oracle, and SQL Server, with Alpine/Ubuntu configurations where defined. Coverage now includes malicious XML, database metadata, multi-message batches, CDATA preservation, and CLI failures. Test execution is faster and less prone to timing races. The repository contains the Docker build; these notes do not announce a new published image or registry tag. [CI harness](https://github.com/OpenIntegrationEngine/engine/commit/ef66d2d56), [CLI smoke tests](https://github.com/OpenIntegrationEngine/engine/commit/ba3fe414e), [file-poll test fix](https://github.com/OpenIntegrationEngine/engine/commit/d9520f9c9).
